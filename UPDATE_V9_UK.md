## Оновлення через Git Bash — повний архів

Розпакуйте `autobazar-v9-game.zip` у «Завантаження». Усередині має бути папка `autobazar-v9`.

Відкрийте Git Bash і виконайте:

```bash
cd ~/Desktop
git clone --branch autobazar-v8 https://github.com/4404903-hash/telegram-containers-app.git autobazar-v9-release
cd autobazar-v9-release
git switch -c autobazar-v9
cp -R ~/Downloads/autobazar-v9/. ./
npm ci --no-audit --no-fund --legacy-peer-deps
npm test
git status --short
git add .
git commit -m "AutoBazar v9: photos, favorites, moderation and refreshed 3D"
git push -u origin autobazar-v9
```

Якщо архів розпакований в іншому місці, змініть шлях у команді `cp`. Якщо папка `autobazar-v9-release` вже існує, оберіть нову назву. Цей спосіб залишає вашу стару робочу папку недоторканою. Не додавайте `.env`, токен бота чи дані бази до Git.

Патч перевірений для коміту `ef9d46a`. Якщо `--check` повідомляє про конфлікт, не застосовуйте його примусово: ваша гілка вже містить інші зміни, які слід зіставити з новою збіркою.

## Render

Перед оновленням зробіть резервну копію PostgreSQL штатними засобами вашого провайдера. Міграції виконуються автоматично під час запуску, зберігають оголошення й повідомлення та додають нові поля й таблиці. Оголошення з минулим терміном дії стануть неактивними.

У налаштуваннях Web Service:

- Branch: `autobazar-v9`.
- Build Command: `npm ci --no-audit --no-fund --legacy-peer-deps`.
- Start Command: `npm start`.
- Health Check Path: `/health`.

Environment:

```text
NODE_ENV=production
DEMO_MODE=false
BOT_TOKEN=ваш_токен_від_BotFather
APP_URL=https://адреса-вашої-гри.onrender.com
DATABASE_URL=адреса_вашої_PostgreSQL
DATABASE_SSL=false
DEVELOPER_USERNAME=s_5994
ADMIN_TELEGRAM_IDS=ваш_числовий_Telegram_ID
```

`DATABASE_SSL=false` підходить, якщо ваш внутрішній URL PostgreSQL не вимагає TLS. Для зовнішньої бази, яка вимагає TLS, установіть `true`; перевірка сертифіката залишається ввімкненою.

Помилка **Startup: BOT_TOKEN is required** означає, що в Environment Render немає значення `BOT_TOKEN`. Вставте справжній токен із BotFather в Render, збережіть і виконайте повторний deploy. Токен не потрібно вставляти у `server.js` або надсилати в чат.

`ADMIN_TELEGRAM_IDS` — числовий ID адміністратора, не `@username` і не токен. Кілька ID — через кому. Без нього подання скарг вимкнене з поясненням. Адміністратор відкриває «Налаштування → Скарги · модерація».

Після розгортання перевірте `/version`: має бути `9.0.0`. Закрийте міні-застосунок Telegram і відкрийте знову, щоб завантажити нові файли.

## Бот і сповіщення

Залиште URL Web App вашого бота спрямованим на цей Render-сервіс. Якщо меню бота ще не налаштоване, у середовищі з установленими `BOT_TOKEN` і `APP_URL` виконайте `npm run setup:bot`.

Гравець має запустити бота або натиснути «Налаштування → Увімкнути Telegram-сповіщення». Нове повідомлення покупця та нагадування про завершення надходять через бота. Банер, звук і показ на заблокованому телефоні залежать від налаштувань Telegram і телефона.

Сервер має працювати постійно для своєчасних сповіщень. Під час зупинки/сну сервісу фонові завдання не виконуються. Відновлені повідомлення обробляються після запуску; попередження про оголошення, яке вже завершилось під час простою, не надсилається.

## Фото та дані

До 3 файлів JPEG/PNG/WebP, кожен до 15 МБ перед стисненням. У браузері вони зменшуються до 1000 px і максимум 450 КБ; сервер повторно декодує їх і зберігає WebP без EXIF. Старі оголошення працюють без фото, міста чи пробігу.

Фото займають місце у PostgreSQL (до приблизно 1,35 МБ на оголошення). Після зняття/завершення фото не видаються покупцям; через 30 днів після завершення їхні байти видаляються. Текст оголошення та історія чатів залишаються. Локальний диск Render для завантажених фото не використовується.

## Локальна перевірка

У Git Bash, у папці проєкту:

```bash
DEMO_MODE=true NODE_ENV=development npm start
```

Відкрийте `http://localhost:3000`, натисніть «Додати приклади». Це демонстраційні оголошення; у production цей маршрут відсутній. Нова публікація дозволяє перевірити свої фото, обране й чат. Для другого тестового профілю відкрийте `http://127.0.0.1:3000`.

## Blender

Відкривайте `.blend` із папки `blend` архіву моделей. `market.blend` — площадка, `office.blend` — офіс, `office-names.blend` — імена з серцями, `car-colors.blend` — 24 варіанти авто. Імена зберігаються окремо і в грі додаються до площадки.

Генератори для повторного створення з папки проєкту:

```bash
"/c/Program Files/Blender Foundation/Blender 4.5/blender.exe" --background --python blender/build_assets.py -- --output public/assets/models
"/c/Program Files/Blender Foundation/Blender 4.5/blender.exe" --background --python blender/build_office_names.py
```

Якщо Blender встановлений в іншому місці, змініть шлях. Готові GLB вже включені; запускати генератори для встановлення гри не потрібно.
